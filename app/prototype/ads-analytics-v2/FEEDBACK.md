## 2. 로컬 결과

- 분석/수집/복구/대조: 80개 중 79개 통과, 실제 Spark 1개 skip.
- 광고 API·명령·오프라인 수집→보고서 HTTP 연결은 외부 DB 없이 검증했습니다. 최종 수량은 PORTING의 실행 기록에 남깁니다.
- 광고 화면·배너·공유 API 관련 38개 테스트, TypeScript·Vite build 통과.
- 전체 프론트의 앞선 회귀는 169개 중 167개 통과였습니다. 기존 시네마틱 자산의 Windows CRLF 해시 검사 2개가 실패했습니다. Git blob은 파일명 해시와 일치하고 checkout을 LF로 정규화하면 원본과 같으며 광고 변경 diff는 없습니다. 광고 범위 밖 자산은 수정하지 않았습니다.

### 최종 합성 관측

Windows AMD64, Python 3.12.10에서 합성 1,000쌍=2,000개 사건을 속도 제한 없이 주입했습니다. publish batch는 100건입니다.

## 3. 남은 실환경 인수

1. 보고 정책·매체·source_id·원본 보관기간을 고정합니다.
2. 실제 MongoDB 권한·replica set, Kafka 토픽·ACL, Spark/JAR·S3A checkpoint를 준비합니다.
3. 브라우저 행동부터 관리자 화면까지 같은 사건 ID·cutoff로 대조합니다.
4. 실제 입력 속도·처리량·종단 지연·중지/재개 후 누락·중복을 측정합니다.
5. AWS 광고→PostgreSQL 허용 등 인프라 계약 차이는 최신 원격 기준으로 별도 검토·적용합니다.

앞선 로컬 코드 개선 단계까지는 commit·push·Issue 변경·배포를 하지 않았습니다. 후속 반영은 광고 시스템 개선 및 평가 피드백 대응 (#13)이라는 이름으로 feature/AD에 커밋·푸시하며 실제 배포는 별도입니다. [실행 가이드](README.md)와 [변경 기록](PORTING.md)을 함께 사용합니다.

### 최종 검증

- 광고 backend 전체 464개 통과, skip 0. 실제 격리 Mongo 전용은 기존 41개+신규 V2 6개이며 나머지는 메모리/모의 회귀입니다.
- 설치된 MongoDB 8.3.7을 새 127.0.0.1 포트·ads-rs·UUID DB로만 실행했습니다. 외부 접속·예기치 않은 자식 실행을 차단했고 시험 DB 잔여 0·프로세스 종료·data 폴더 정리를 확인했습니다.
- 반복 검증 중 기존 테스트의 전역 time 모의가 Mongo 백그라운드 스레드에 영향을 주는 시험 격리 문제도 발견했습니다. 대상 모듈의 clock만 모의하도록 바꾼 후 464개가 통과했습니다. 실제 예산 주기·정책 코드는 바꾸지 않았습니다.
- 분석 core 93개 중 92개 통과, 실제 Spark 1개 skip. 100,001건에서 rows·totals·diagnostics·dataset_sha256·report_id 전체가 참조 구현과 일치했습니다.
- 위 시험은 원본 행 보존·임시 spool 정리·Python tracemalloc peak 16MiB 미만도 확인했습니다. 전체 프로세스 RSS나 실제 Spark 성능의 측정은 아닙니다.
- frontend 전체 210개 통과. 광고/공유 API 관련 77개·TypeScript·Vite build 통과.
- 실제 Edge+합성 API 11개: 업로드·미리보기·등록·큰 정수 거부·동일 내용 새 등록·시각 보존 수정·중단·대기/0건·잘못된 응답·재조회·권한 제한 통과. 실제 공통 인증 서버의 종단 시험은 아닙니다.
- 기존 Windows checkout의 시네마틱 hash 실패 2개는 해당 generated JS/CSS만 .gitattributes로 바이트를 보존하고 HEAD 원본으로 복원했습니다. 자산 내용·해시는 변경하지 않았습니다.
- 광고 관련 Compose 5개 profile 각각 단독 config 검증 통과. 실제 Docker 이미지 빌드·기동은 미실행입니다.
