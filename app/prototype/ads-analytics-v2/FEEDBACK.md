## 2. 로컬 결과

- 분석/수집/복구/대조: 80개 중 79개 통과, 실제 Spark 1개 skip.
- 광고 API·명령·오프라인 수집→보고서 HTTP 연결은 외부 DB 없이 검증했습니다. 최종 수량은 PORTING의 실행 기록에 남깁니다.
- 광고 화면·배너·공유 API 관련 38개 테스트, TypeScript·Vite build 통과.
- 전체 프론트의 앞선 회귀는 169개 중 167개 통과였습니다. 기존 시네마틱 자산의 Windows CRLF 해시 검사 2개가 실패했습니다. Git blob은 파일명 해시와 일치하고 checkout을 LF로 정규화하면 원본과 같으며 광고 변경 diff는 없습니다. 광고 범위 밖 자산은 수정하지 않았습니다.

### 최종 합성 관측

Windows AMD64, Python 3.12.10에서 합성 1,000쌍=2,000개 사건을 속도 제한 없이 주입했습니다. publish batch는 100건입니다.

| 관측 | 결과 |
|---|---:|
| 저장·발행·소비·재처리·집계·대조 | 20.953초 |
| 고유 사건 처리량 | 약 95.45건/초 |
| publish 배치 p50 / p95 | 1,024.10 / 1,203.56ms |
| ACK 후 중단 포함 전송 | 2,001회 |

메모리 broker·실제 SQLite 측정이며 실제 Kafka/MongoDB/Spark 성능·사건별 종단 지연·운영 SLA가 아닙니다. 입력은 합성이며 CTR 100%는 생성 조건의 결과입니다. 원본 보관·수집 완전성은 검증하지 않았습니다. 이 검증 폴더의 .local/feedback-benchmark-20261109-final/evidence.json은 Git 제외 로컬 증거입니다. 다른 기기에서 같은 속도를 보장하지 않습니다.

## 3. 남은 실환경 인수

1. 보고 정책·매체·source_id·원본 보관기간을 고정합니다.
2. 실제 MongoDB 권한·replica set, Kafka 토픽·ACL, Spark/JAR·S3A checkpoint를 준비합니다.
3. 브라우저 행동부터 관리자 화면까지 같은 사건 ID·cutoff로 대조합니다.
4. 실제 입력 속도·처리량·종단 지연·중지/재개 후 누락·중복을 측정합니다.
5. AWS 광고→PostgreSQL 허용 등 인프라 계약 차이는 최신 원격 기준으로 별도 검토·적용합니다.
