# BRD · 핏플레이스·뮤더 통합 프로젝트

- 작성일 : 2026-11-12

## 1. 프로젝트 개요

### 프로젝트 내용
**itda** - 음악 큐레이션 서비스(track1)와 주변 매장 탐색 서비스(track2)를 이어주는 서비스

### 운영중인 서비스
- **muther**: 날씨와 분위기 등 추천 조건을 설정해 음악을 추천받고 재생하는 B2B 서비스.(이하 track1)
- **핏플레이스**: 지역, 날씨, 분위기, 예산 등을 고려해 카페와 주점 등 주변 매장을 탐색하는 B2C 서비스.(이하 track2)

## 2. 프로젝트 배경과 문제 정의

### 2-1. 추진 배경
- track1의 음악 추천 정확도를 올려 사용자의 의도에 맞는 음악을 선곡하기 위함
- 매장 운영자 대상인 track1의 이용 타겟을 일반 사용자로 확장하기 위함


### 2-2. 해결하려는 문제

|범위|문제|
|---|---|
| 공통 | track1 서비스만으로 일반 고객을 매장으로 유치하기 어려움 |
| track1 | 날씨와 매장 분위기를 모두 고려하여 음악을 선정하기 어려움 |
| track1 | 추천 범위의 한정, 의도와 다른 선곡으로 재탐색의 수고가 발생함 |
| track2 | 날씨와 기분을 고려하여 주변 매장을 탐색하기 어려움 |
| track2 | 주어진 예산에 맞는 가게를 탐색하는 수고가 발생함 |
| track2 | 매장에서 흘러나오는 음악 정보를 실시간으로 파악할 수 없음 |
| track2 | 애견 동반, 룸 유무 등 특수 조건을 확인하기 어려움 |
| track2 | 주변 매장의 할인, 이벤트 정보를 파악하기 어려움 |

## 4. 프로젝트 이해관계자

| 담당 영역 | 주요 역할 | 주요 협의·확인 사항 |
|---|---|---|

| track2 백엔드·매장 추천 | 매장·메뉴 조회와 장소 추천에 필요한 API와 데이터 처리를 담당한다. 이벤트 발행·참여, QR 인증과 알림 기능의 요구사항 및 연동을 검토한다. | 매장·메뉴 데이터의 출처와 사용 범위, 검색·추천 조건, API 응답과 데이터 누락 시 처리, 이벤트·QR의 시연 범위를 확인한다. |

## 7. 주요 비즈니스 요구사항

### 7-1. 공통 계정과 서비스 연동

- 이용자는 로그인 후 해당 서비스에 접근할 수 있어야 한다.
- 뮤더 이용 매장을 핏플레이스에 파트너 매장으로 표시하고, 해당 매장에서 현재 재생 중인 음악을 확인할 수 있어야 한다.
- 사용자 유형별 접근 권한과 매장 연결·표시 조건은 확인이 필요하다.

### 7-2. track1 · 음악 추천과 재생

- 매장 운영자는 날씨와 취향 등 추천 조건을 설정하고 음악을 추천받아 재생할 수 있어야 한다.
- 기존 음악 기능과 DB 개선, 음악 장르·분위기 분류 및 평가 범위를 정리한다.

### 7-3. track2 · 매장 탐색과 이용

- 사용자는 조건 검색 또는 지도로 매장을 탐색하고 상세·메뉴 정보를 확인할 수 있어야 한다.
- 사용자는 찜·리뷰와 인원·예산을 고려한 메뉴 조합을 이용할 수 있어야 한다.
- 이벤트·QR 기능의 시연 범위와 상세 정책은 확인이 필요하다.

### 7-4. 데이터 누락과 연결 장애

- 재생할 음악 데이터가 없으면 해당 곡을 건너뛴다.
- 매장 데이터가 없으면 ‘서비스 준비중’을 표시한다.
- 메뉴 사진, 메뉴 이름 또는 가게 설명이 없으면 해당 정보를 별도로 표시하지 않는다.
- 연결이 끊기면 스피너를 표시하며 복구를 시도하고, 10초가 지나면 ‘일시적인 문제가 발생했어요.’를 표시한다.

위 항목은 요구사항과 처리 방침이며, 기능별 상세 조건과 검증 기준은 PRD에서 정한다.

## 8. 데이터 관리 원칙

### 8-1. 데이터 출처와 사용 범위

- 음악 추천과 매장 탐색에는 실제 데이터를 사용한다. 음악·매장·메뉴·날씨 데이터별 출처와 사용 범위를 확인한다.

### 8-2. 데이터 처리와 갱신

- 음악 데이터의 적재 상태와 사용자 피드백의 적재 여부를 확인한다.
- 매장·메뉴·날씨 데이터의 갱신 주기와 품질 확인 기준은 담당자 확인 후 정한다.

### 8-3. 서비스 간 데이터 연결

- 뮤더 이용 매장과 핏플레이스 매장을 연결하고, 파트너 정보와 현재 재생 음악을 표시하기 위한 데이터 기준을 정한다.
- 매장 식별과 재생 정보의 전달·갱신 방식은 확인이 필요하다.

## 9. 성공 기준

평가는 기능 시연을 중심으로 한다. 구체적인 입력 조건과 통과 기준은 PRD 및 시연 시나리오에서 확정한다.

| 범위 | 시연에서 확인할 내용 |
|---|---|
| track1 | 음악 데이터의 적재, 조건에 따른 음악 추천, YouTube 연계 재생, 사용자 피드백의 데이터 적재를 확인한다. |
| track2 | 설정한 조건에 따른 매장 추천, 현재 위치·선택 지역 기준 검색과 매장 상세 정보 표시를 확인한다. |
| 서비스 연동 | 뮤더 이용 매장의 파트너 정보와 현재 재생 음악이 해당 매장에 표시되는지 확인한다. |
| 공통 | 시연에 사용한 데이터와 환경을 기록하고 합의된 데이터 누락·연결 장애 처리를 확인한다. |

서버 연동 후 시연하고, 시연 후 음악 추천과 장소 추천 데이터의 조회·표시를 QA한다.

## 10. 제약과 전제 조건

- **현재 상태:** 로컬 구현은 완료됐으나 서버 연동은 대기 중이며 현재 시연은 불가능하다. 기능별 연동·검증 상태는 별도 확인한다.
- **시연 전제:** 서버 연동, 실행 환경, 계정과 데이터 준비가 필요하다.
- **데이터 제약:** 실제 데이터의 출처·사용 범위와 갱신 기준을 확인해야 한다.
- **외부 의존성:** YouTube 연계 재생과 날씨 데이터 조회의 연결 조건·장애 영향을 확인해야 한다.
- **정책 및 연동:** 사용자별 접근 권한, 위치 사용, 매장 식별과 재생 정보 전달의 세부 조건을 확인해야 한다. QR의 범위는 미정이다.
